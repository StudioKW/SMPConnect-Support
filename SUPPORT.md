# Support

For ordinary bugs, use the [Bug report form](https://github.com/StudioKW/SMPConnect-Support/issues/new?template=bug_report.yml). For improvements, use [Feature request](https://github.com/StudioKW/SMPConnect-Support/issues/new?template=feature_request.yml). [Search existing issues](https://github.com/StudioKW/SMPConnect-Support/issues) first and keep one problem per report. Reports and feature discussions are public.

Include the exact SMPConnect version, Minecraft version, Paper build, Java version, a short problem description, reproduction steps, expected result and actual result. Add only short **sanitized** log excerpts when useful. Do not upload complete server logs, world files, player databases, authentication/session data, tokens, credentials, private messages, player names/UUIDs or IP addresses. Replace identifying values with consistent labels such as Player A and Player B. Screenshots must hide personal information and show a real observation.

Before reporting: confirm the documented Paper/Java target, restart normally, check the SMPConnect readiness message and review configuration ranges. If a database error occurs, stop and preserve a private backup; do not delete/recreate the database to make the message disappear. Never use `/reload` to diagnose lifecycle behavior. Explain the actual action and feedback; “the server starts” alone does not describe a menu problem.

For a suspected vulnerability, **do not open an issue or paste exploit details here**. Follow [SECURITY.md](SECURITY.md). If you accidentally disclose a secret, revoke or rotate it immediately and privately alert the repository administrator; editing a public comment does not guarantee its history or copies disappear.

Current documented beta target: SMPConnect 0.1.0, Minecraft 26.3 / Paper build 249 / Java 25. Other platforms/builds may be unsupported. Feature requests are suggestions, not commitments. Support is provided as available without a guaranteed response time or maintenance period.
