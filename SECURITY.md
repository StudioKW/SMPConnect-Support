# Reporting a vulnerability

**Do not report vulnerabilities in public GitHub Issues, feature requests, comments or screenshots.**

GitHub private vulnerability reporting is enabled for **StudioKW/SMPConnect-Support**. Open [Report a vulnerability](https://github.com/StudioKW/SMPConnect-Support/security/advisories/new), or go to this repository's Security → Advisories page and choose Report a vulnerability. GitHub may require you to sign in.

This confidential reporting channel is for SMPConnect even though this repository contains support documentation rather than plugin source. Ordinary bugs belong in public Issues only when they do not expose a security weakness or sensitive information.

Privately include the affected plugin version, Minecraft/Paper build, Java version, impact, prerequisites and a minimal reproduction. Provide only sanitized relevant output. Never send live credentials, complete player databases or unrelated personal information. Test only servers and data you own or have permission to assess.

If the private reporting button becomes unavailable, **do not post details publicly**. Wait until the publisher provides a working confidential channel. No security email or alternative endpoint is claimed.

Current beta scope is SMPConnect 0.1.0 on the documented Paper target. There is no guaranteed response time, bounty or maintenance period. The publisher will assess reports and coordinate any disclosure. A private report is not automatically a public advisory; do not publish proprietary source, private logs or player data in a later advisory.

GitHub describes the mechanism in its [private reporting documentation](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository).
